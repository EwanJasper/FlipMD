桌面端已经接入的功能如下；“已接入”表示代码和调用流程已实现，完整的实机验证范围在下文单独列出。

| 功能 | 已实现的行为 |
| --- | --- |
| 文件导入 | 单个、多个 PDF/DOCX，以及文件夹当前层导入；重复文件去重；已接入拖入事件，跨应用拖入仍待实测 |
| 转换操作 | 单文件、批量、合并及合并顺序调整；Markdown/HTML 输出；图片提取、页码范围、文本清理和表格相关选项 |
| 参数管理 | 本次任务参数与全局默认设置分开；任务保存提交时的参数快照 |
| 后台任务 | 后台串行处理、状态显示和错误记录；停止时完成当前文件，再停止后续文件 |
| 任务历史 | 本地 SQLite 保存任务、子文件、结果、大纲摘要和日志；支持搜索、筛选、查看结果及删除记录 |
| PDF 原文对照 | 从源 PDF 渲染实际页面，与 Markdown 并排显示 |
| Word 原文对照 | 从源 DOCX 独立读取标题、正文、表格和内嵌图片；提供内容预览，不还原 Word 分页或复杂排版 |
| 阅读和导出 | Markdown 阅读与源码切换、复制、保存导出、打开输出位置；大纲、摘要和处理详情 |
| 日志 | 查看、复制选中内容、复制全部及导出日志 |
| 文件保护与恢复 | 自动转换遇到输出重名时添加序号；图片独立保存并缓存，支持重新导出；源文件缺失时已有结果仍可阅读；删除任务记录不删除源文档和导出文件 |
| 配置与异常恢复 | 首次读取旧配置，新客户端设置独立保存；异常退出后的未完成任务标记中断；同一数据目录使用进程锁 |
| OCR 状态 | 保留原有可选 OCR 能力和语言设置；依赖缺失时显示不可用，当前应用包没有内置 PaddleOCR |

开发和验收过程中还修复了两处实际问题：

- 原引擎可能将全文字表格的所有行都识别为表头，导致整张表丢失。已加入首个非空行作表头、其余行作数据的回退逻辑，并补充回归测试。
- macOS 原生文件选择器的筛选说明中使用斜杠会引发问题。已调整 PDF/Word 筛选说明和文件夹选择参数，并补充契约检查。

最近一次完整测试为 **257 项通过**。Ruff 检查、`git diff --check`、Windows 构建参数预演、PowerShell 片段的 tree-sitter 静态解析，以及工作流 YAML 解析均通过。源码自检通过真实 PDF/DOCX 转换、PDF 渲染、Word 原文预览、HTML 导出、界面资源和 SQLite 历史恢复检查。

macOS 打包后的原生窗口已验证：系统文件/文件夹选择、重复导入去重、PDF/DOCX 批量转换、两种原文对照、合并顺序、Markdown 源码、大纲统计、系统保存面板导出，以及关闭后重启保留任务历史。macOS 阶段的完整测试为 244 项，Windows 准备阶段补充检查后增至 257 项。

Windows 安装方案已写明默认按当前用户安装，开始菜单入口、可选桌面快捷方式、WebView2 检测和缺失时安装、卸载保留用户数据，并准备生成安装程序、便携版和 SHA-256 校验文件。手动 GitHub Actions 工作流还包含安装后自检和诊断报告收集，但尚未执行。Windows 安装器目前使用英文界面，应用界面为中文。
